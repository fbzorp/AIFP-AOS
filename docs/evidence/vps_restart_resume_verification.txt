## Expected Behavior After VPS Reboot

1. Docker daemon starts automatically (via systemd)
2. Docker Compose automatically restarts all services with `restart: unless-stopped`
3. Services start in dependency order:
   - postgres (health check)
   - redis (health check)
   - api (depends on postgres/redis healthy)
   - worker (depends on postgres/redis healthy)
   - dashboard (no dependencies)
   - nginx (depends on api started, cert-init completed)
4. cert-init runs once (only on first deployment or if certificates are missing)
5. Nginx waits for API to be healthy before starting
6. Worker resumes processing any pending tasks from Redis queue

## Restart Policy Verification

All long-running services use `restart: unless-stopped` which means:
- Services automatically restart on Docker daemon restart
- Services automatically restart on VPS reboot
- Services do NOT restart if manually stopped with `docker compose stop`
- This is the recommended policy for production services

The `cert-init` service uses `restart: "no"` which means:
- Service runs once and exits
- Does not restart automatically
- Only runs when explicitly started via `docker compose up`
- This is correct for a one-shot initialization service
